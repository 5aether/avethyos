# AvethyOS

AvethyOS is a Fedora bootc desktop with Hyprland and Quickshell.

## Updates

Update the installed system with:

```bash
sudo bootc upgrade
```

Reboot to start the updated deployment. Bootc keeps the previous deployment for
rollback.

Quickshell and the required Hyprland configuration are part of that deployment.
Publishing an image with changes to `quickshell/` or the managed files in `hypr/`
updates the desktop on users' next `bootc upgrade` and reboot. The files live in
`/usr`, which is managed with the image rather than persistent home directories
([bootc filesystem documentation](https://bootc.dev/bootc/bootc-filesystem.7.html)).

| Installed path | Purpose |
| --- | --- |
| `/usr/share/avethyos/quickshell/` | Read-only shell code, helpers, fonts, styles, and shaders. |
| `/usr/share/avethyos/hypr/` | Read-only compositor entry point, session environment, shell layer rules, and shell commands. |
| `~/.config/hypr/` | User-owned shortcuts, monitors, input, appearance, window rules, custom configuration, and lock/idle preferences. |
| `~/.local/state/avethyos/quickshell/config.ini` | Persistent shell settings, including wallpaper and notification preferences. |
| `~/.local/state/avethyos/hypr/theme.lua` | Wallpaper palette generated by Quickshell. |

These user paths respect `XDG_CONFIG_HOME` and `XDG_STATE_HOME`. Defaults are
created only when missing; system updates never replace an existing user file.
Empty Lua files can disable that set of user defaults. New default templates can
be inspected in `/usr/share/avethyos/hypr/user/`.

Edit `~/.config/hypr/shortcuts.lua` to change keybindings. Its `--` comments explain
the available shell commands and show how to add a shortcut. Commands such as
`appmenu`, `control_center`, and `clipboard` come from the image's `commands.lua`,
so owner changes to their implementation apply without replacing user shortcuts.
Hyprland watches the loaded Lua files; `hyprctl reload` also reloads them manually.

The login wrapper always selects `/usr/share/avethyos/hypr/hyprland.lua`, and shell
startup and IPC select `/usr/share/avethyos/quickshell` explicitly. Ordinary users
can edit their own preferences; the installed system files are root-owned and
have no group or other write permission.

On the first login after upgrading from the old home-directory layout, the user
initializer preserves shell settings and backs up the old desktop files under
`~/.local/state/avethyos/legacy-desktop/`. It migrates the supported old Hyprland
layout into user modules. Unrecognized custom configurations remain in the
backup for manual transfer into `~/.config/hypr/custom.lua`; they are not executed
alongside the new system integration.

Published standard and NVIDIA images are split into content-based layers with
[chunkah](https://github.com/coreos/chunkah). Bootc reuses layers already present
on the system and downloads changed layers. A package or desktop configuration
update can therefore download only a fraction of the image.

This works at the layer level: a changed layer can contain unchanged files too.
Large package updates, changes to package grouping, and Fedora version upgrades
can still require larger downloads. The first upgrade from an older, unchunked
image can download most of the image; subsequent upgrades reuse the new layout.

The build uses stable directory timestamps, a fixed timestamp when splitting
layers, and reproducible initramfs generation to reduce changes caused only by
rebuilding or package installation. The publishing workflow reports the full
compressed image size and the estimated download from the previous image of the
same variant. This estimate counts new layer digests; it does not include metadata
or reflect clients upgrading from older releases.

## Kernel preferences

Set Apple keyboard function keys to F1–F12 first:

```bash
sudo avethyos fnmode 2
```

Reboot to apply the setting. This sets `hid_apple.fnmode=2`; it applies to keyboards
using the Linux `hid_apple` driver. Modes are `0` (disabled), `1` (media keys first),
`2` (F keys first), `3` (automatic), and `4` (F keys disabled). Use
`sudo avethyos fnmode default` to remove your override.

Other kernel arguments use the same interface:

```bash
avethyos kernel show
sudo avethyos kernel set hid_apple.fnmode=2
sudo avethyos kernel add console=tty0 console=ttyS0
sudo avethyos kernel remove console=ttyS0
sudo avethyos kernel remove console
sudo avethyos kernel reset
```

`set` replaces your values for the supplied names, leaving other preferences
alone. `add` permits repeated names; `remove` accepts an argument name or an exact
`name=value`. `reset` removes all arguments managed by this command. Each argument
is a separate command-line token. Values containing whitespace, quotes or
backslashes are rejected to avoid changing their meaning during serialization.

Preferences live in `/etc/avethyos/kernel-arguments.json`, which survives image
updates. The command uses bootc's native `loader-entries set-options-for-source`
API with its own `avethyos-user` source; it does not invoke rpm-ostree or install
packages. Image arguments, other sources, and a staged system update remain
intact. A parameter already set elsewhere may occur more than once; precedence
depends on that particular kernel parameter. `remove` and `reset` only remove
your managed arguments. See the [bootc source API documentation](https://bootc.dev/bootc/internals/bootc_lib/loader_entries/index.html).

Changes require a reboot. Continue using `sudo bootc upgrade` for system updates.
If staging fails, the command reports the error and keeps the desired preferences
marked pending. After resolving the error, run `sudo avethyos kernel apply` to
retry. The image requires bootc 1.16.13 or newer and ostree 2026.1 or newer.

## Native applications

The standard image includes native RPM applications, including GNOME Disks and
GParted. Their updates arrive with `bootc upgrade`.

An arbitrary additional native RPM must become part of an OS image to retain
that update model. Installing it with `rpm-ostree install` creates local package
layering, which [prevents bootc upgrades](https://bootc.dev/bootc/bootc-relationships.7.html).
A command wrapper cannot remove that restriction. [Bazzite's native RPM installation](https://docs.bazzite.gg/Installing_and_Managing_Software/rpm-ostree/)
uses rpm-ostree layering too.

To support native apps beyond the standard image, either add them to this
project's package lists or build and publish a personal bootc image containing
the selected RPMs. A personal image must be rebuilt when its AvethyOS base changes;
clients then use `bootc upgrade` against that image's registry tag. Apps run on the
host in either case. No arbitrary native app installer is provided yet.

## Local image builds

Run rechunking after building and before pushing a local image:

```bash
just build
just rechunk
```

For NVIDIA:

```bash
just build-nvidia
just rechunk avethyos nvidia
```

Rechunking checks the resulting image with `bootc container lint` before replacing
the local image tag. GitHub Actions performs this step for both variants before
tagging, publishing, and signing them.
